# Текущее состояние Pocket Overlord

Дата аудита: 25 октября 2026. Основание: чтение текущего рабочего дерева, включая незакоммиченные изменения. Это карта существующего кода для отдельных планов, а не утверждение о полном соответствии WorldBox. Перед реализацией любого плана повторно проверить затрагиваемые файлы: проект меняется параллельно.

## Правила использования

- Выполнять выбранный план; не внедрять соседние планы автоматически.
- Сохранять уже существующие механики и чужие изменения. Не делать commit/push без прямой просьбы пользователя.
- Факты WorldBox брать из источников конкретного плана. Баланс Pocket Overlord ниже — собственные значения проекта, не цифры WorldBox.
- Наличие типа, картинки или инструмента не означает, что у элемента есть все взаимодействия из wiki.
- Этот аудит не запускал тесты и не менял `src/` или `tests/`; наличие теста ниже означает существующее покрытие, а не свежий успешный прогон.

## Основа симуляции

- TypeScript + Vite, собственный Canvas-рендер: `src/main.ts`, `src/render/renderer.ts`, `src/input/controller.ts`, `src/ui.ts`.
- Сущности состоят из компонентов. Общие типы: `src/core/types.ts`; дополнительные компоненты объявляют контентные модули.
- `src/content/registry.ts`: регистрация сущностей, компонентов с валидаторами, инструментов, событий, систем и сценариев. Контент подключается в `src/content/defaults.ts`.
- `src/core/world.ts`: создание мира, случайность, индексы компонентов, пространственный поиск, команды, события, сохранение. `src/core/systems.ts` и `src/systems/index.ts`: порядок обновления систем.
- Симуляция имеет фиксированный шаг 1/30 секунды. Пауза и скорости 0.2/1/2/4/10/40; сохранение включает seed, состояние RNG и tick.
- Текущие пределы: карта 512×384, 300 жителей, 6000 сущностей, бюджет 256 событий. Не увеличивать пределы попутно; массовые новые виды требуют проверки стоимости обновления.
- Контентные пакеты — программный механизм расширения на этапе сборки. Общего пользовательского редактора видов/рецептов/модов нет.

## Камень: уже реализованная цепочка

- `src/content/stone.ts`: `core:stone`, случайное размещение при создании мира и инструмент «Природа → Камень». Независимый RNG с seed мира; число попыток `floor(width * height / 240)`. Реальных залежей меньше: вода, препятствия и соседние залежи отбрасываются.
- Пользователь отдельно потребовал случайное распределение и затем уменьшение количества примерно вдвое. Текущую плотность не возвращать к прежней без просьбы.
- Место: свободная трава или песок, безопасная суша; залежь физически мешает проходу. Запас 24, здоровье 120; компонент горючести отсутствует.
- Добыча взрослым жителем после реального подхода; партия до 4 единиц. Залежь истощается и удаляется. Вода после изменения суши удаляет залежь.
- `src/systems/economy.ts`: добыча → переносимый груз → доставка в рынок → запас деревни. До прибытия камень не зачисляется. Голод может прервать работу, сохранив груз.
- `src/systems/construction.ts`: улучшение готового обычного дома требует 8 камня + 2 дерева, списывает их один раз, требует работы строителей. После завершения вместимость 5→7, здоровье +120. Каменная отделка не отключает существующее горение дома.
- Мастерская создаёт каменный топор из 2 камня + 1 дерева. Его сначала доставляют в запас. Взрослый житель физически получает топор на рынке; оружие даёт +4 к урону.
- `src/core/stone.ts`: все перечисленные стоимости и бонус. `src/render/construction.ts`, `src/render/residents.ts`: каменные дома, кирка, грузы, топоры.
- `src/systems/recovery.ts`: восстановление разрушенного улучшенного дома возвращает базовый дом, а не бесплатное улучшение.
- `tests/stone.test.ts`, `tests/browser/stone.spec.ts`: генерация, физическая добыча/доставка, однократное списание, экипировка, урон, миграция сохранения, автономная цепочка, UI.
- Пока нет шахт, каменных стен/дорог, нескольких каменных орудий, качества/прочности предметов, торговли камнем, специфических каменных зданий разных народов, природного возобновления залежей.

## Ресурсы, еда и производство

- `src/core/village-life.ts`: товары `grain`, `flour`, `bread`, `wood`, `tools`, `stone`, `stoneAxes`; общий запас принадлежит деревне. Отдельно существует числовой `village.food`.
- `src/systems/economy.ts`: рынок, мельница, пекарня, мастерская; реальные работники и перенос партий. Рецепты: 2 зерна→2 муки; 2 муки→4 хлеба; 3 дерева→2 инструментов; каменный топор см. выше.
- Дерево получают вырубкой настоящих `core:tree`. Инструменты участвуют в хозяйстве; это общий расходуемый запас, не полноценная личная экипировка.
- `src/systems/society.ts`: создание доступных полей, рост, уборка, плодородие. `src/systems/people.ts`: голод, потребление еды, ущерб от голода.
- Поля требуют пригодного участка 3×3 и достижимости по суше; лёд, каменная поверхность и водная поверхность не подходят. Вода/разрушение грунта лишают поле пригодности.
- `src/core/seasons.ts`: весна/лето/осень/зима, по 1800 тиков; зимний рост и урожай отключены, аппетит растёт. Сезоны влияют на запасы, перевозки и животных.
- Рынок и производственные здания появляются автономно по условиям деревни; для их первоначального создания нет полной материальной сметы и строительного процесса, аналогичного улучшению дома.
- Нет железа, меди, золота, серебра, мифрила, адамантина, драгоценностей и отдельной экономики валюты. Нет общей системы разных пищевых предпочтений, качества пищи, налогов, цен, торговли всеми товарами и профессий как постоянных социальных ролей.

## Жители, личность, родство

- `src/core/races.ts`, `src/content/peoples.ts`: люди, эльфы, орки, гномы. Отличаются здоровьем, скоростью, сроком жизни, боем, восстановлением, строительством, прочностью дома и дипломатическими склонностями.
- `src/core/types.ts`: возраст, условный пол `a/b`, дом, партнёр, родители, голод, беременность, отец ребёнка, текущая работа/маршрут, вклад в деревню.
- `src/systems/people.ts`: взросление, старение, постоянные пары, родство, беременность/рождение, поиск жилья, стройка, работа, бой, перемещение, плавание к берегу. Родство учитывается при выборе пары.
- Жители имеют стабильные генерируемые отображаемые имена (`residentName` в `src/core/village-life.ts`), но нет полноценного сохранённого профиля имени/биографии/опыта.
- `src/systems/emergencies.ts`: бегство, тушение и помощь; детское поведение учитывается отдельно. `src/core/resident-animation.ts` и `src/render/residents.ts`: действия отражены анимацией.
- `src/systems/migration.ts`: семейные группы, резервы жилья, физическое переселение, основание новых поселений. `src/systems/integration.ts`: адаптация после прибытия, работа, встречи/друг, изоляция, повторный поиск места.
- Нет общей системы наследуемых черт, генов/подвидов, уровней/опыта, навыков, индивидуального инвентаря, слотов брони, редкости/авторства/прочности оружия. `weapon?: 'stone-axe'` — один тип оружия, не общий движок предметов.
- Нет общей сети всех отношений/воспоминаний/биографий: партнёр/родители и друг при адаптации решают конкретные задачи существующих систем.

## Поселения, политика, войны

- `src/core/types.ts`: деревни, парные отношения, дороги, коалиционные войны, миграции, короткая мировая хроника.
- `src/systems/society.ts`: принадлежность домов и жителей, основание/исчезновение деревень. Поселения и жильё разделены по народу.
- `src/systems/governance.ts`: выбор старейшины по вкладу/возрасту, доверие, перевыборы, потеря доверия из-за голода и военных потерь.
- `src/core/diplomacy.ts`, `src/systems/diplomacy.ts`: нейтралитет/союз/война, объединённые стороны, сбор войска, цели, подкрепления, потери, перемирие, доступность пути.
- `src/systems/people.ts`: реальное движение и ближний бой с уроном, часть населения продолжает хозяйство.
- `src/systems/caravans.ts`: перевозка еды между дружественными поселениями с сохранением собственного резерва. Это не торговый рынок произвольных ресурсов.
- `src/content/settlement-names.ts`: устойчивые имена деревень с локализацией. Хроника хранит максимум 40 сообщений, а не полную историю мира.
- Нет отдельного уровня королевств с территориями и захватом деревень, династий/кланов/наследования власти, культур/исследований/религий, дипломатических замыслов и общих законов мира. Союз нескольких деревень не считать готовым королевством.
- Основные тесты: `tests/society.test.ts`, `tests/diplomacy.test.ts`, `tests/migration.test.ts`, `tests/integration.test.ts`, `tests/peoples.test.ts`, `tests/village-life.test.ts`.

## Здания, дороги, транспорт

- Дом и поле — `src/content/defaults.ts`; рабочие здания/животные — `src/content/village-life.ts`; порт/корабль — `src/content/seafaring.ts`.
- Базовые дома строят жители; до завершения стройки нет готового жилья. Работу могут продолжить другие жители. Разрушение оставляет руины, возможны восстановление и переселение.
- `src/core/roads.ts`, `src/systems/society.ts`, `src/systems/road-repair.ts`: прокладка дорог, мосты, повреждение/ремонт, зарастание неиспользуемых дорог; дороги ускоряют движение.
- `src/core/ferries.ts`, `src/systems/ferries.ts`: паромы перевозят настоящих пассажиров, вместимость 6; короткий мост до 3 клеток, паромный пролёт до 24.
- `src/core/seafaring.ts`, `src/systems/seafaring.ts`: прибрежные порты, рыболовные и торговые парусники, безопасный морской маршрут, возврат/разгрузка. Корабельный груз — число еды, не набор всех товаров.
- Рыба в этой цепочке — результат рыбалки, не отдельные сущности рыб с популяцией. Морские корабли не равны паромам с жителями; не обещать морской десант на основании наличия `ship`.
- Нет полной линейки зданий каждого уровня, защитных стен/башен, культурных/религиозных сооружений, ресурсных шахт и общего каталога строительных рецептов.
- Тесты: `tests/construction.test.ts`, `tests/recovery.test.ts`, `tests/house-collapse.test.ts`, `tests/roads.test.ts`, `tests/crossings.test.ts`, `tests/seafaring.test.ts`, `tests/caravans.test.ts`.

## Мир, биомы, растения и животные

- `src/core/terrain.ts`: суша/вода/глубокая вода/песок/трава/горы, дороги/мосты, воронки/выжженная земля, влажность, восстановление повреждённой поверхности.
- `src/core/biomes.ts` содержит формы островов Dragon/Turtle/Phoenix/Kraken/Whale/Yin-yang. Это формы карты; они не означают наличие соответствующих животных.
- `src/core/natural-biomes.ts`: Grassland, Savanna, Desert, Jungle, Swamp, Permafrost, Enchanted, Corrupted, Infernal, Mushroom, Crystal, Candy, Lemon.
- Биом влияет на внешний вид земли/деревьев, плотность деревьев, скорость движения и рост урожая. Есть локальные покрытия почва/камень/песок/грязь/вода/лёд, независимые от формы острова.
- `src/content/natural-biomes.ts`: кисти биомов и посадка растительности; Crystal/Candy не входят в `SEED_BIOMES`, хотя представлены в данных/генерации.
- Все варианты биомных деревьев — сущности `core:tree`; декоративные кристаллы/конфетные деревья не означают добычу отдельного ресурса. Каменная поверхность биома не равна залежи `core:stone`.
- `src/systems/landscape.ts` восстанавливает повреждённый грунт и старит дороги; это не общая система размножения/распространения растений.
- `src/core/village-life.ts`, `src/systems/husbandry.ts`: овцы, собаки, волки; голод/кормление, размножение овец, производство еды, связь собаки с хозяином, защита стада и нападения волков. Стада/угрозы возникают через условия поселения.
- Нет полной экосистемы уникальных биомных животных/растений, пищевых сетей, специализированного плодоношения, общего механизма превращения существ в биомах. Особые биомы пока не задают полные правила зачарования/порчи/инфекций.
- Тесты: `tests/natural-biomes.test.ts`, `tests/terrain.test.ts`, `tests/terraforming.test.ts`, `tests/seasons.test.ts`, `tests/village-life.test.ts`.

## Силы, болезни, разрушения

- `src/systems/effects.ts`: урон, нагрев, намокание, огонь, взрывы, импульсы, изменение грунта. Контент подключает собственные обработчики/сценарии.
- Уже зарегистрированы динамит, ракета, гроза, напалм, Hammer of Dawn, Tsar Bomba, дракон, летающая тарелка, управляемый гигантский кайдзю, кровавый торнадо, гравитационный хлопок, кислота, вулкан, чума и безумие.
- Их реализация находится в одноимённых `src/content/*.ts`, части `src/core/*.ts`, `src/render/*.ts`; это работающие индивидуальные модели поведения, не универсальная коллекция всех WorldBox powers.
- `src/content/terraforming.ts`: поднятие/опускание суши. `src/content/thunderstorms.ts`: облака, дождь/молнии.
- `src/core/afflictions.ts`, `src/systems/afflictions.ts`, `src/content/afflictions.ts`: заразная чума с инкубацией, контактом и уроном; безумие нарушает обычные задания и вызывает нападения с ответной защитой. Состояния действуют на жителей четырёх народов.
- Нет общего каталога длительных эффектов/иммунитетов/исцеления, зомби/скелетов/грибной инфекции и большинства отдельных существ/сил wiki. Наличие компонента `thermal` само по себе не задаёт все взаимодействия с лавой/льдом/ядами.
- Тесты распределены по `tests/afflictions.test.ts`, `tests/cataclysms.test.ts`, `tests/geohazards.test.ts`, `tests/dragons.test.ts`, `tests/ufos.test.ts`, `tests/kaiju.test.ts`, `tests/napalm.test.ts`, `tests/superweapons.test.ts`, `tests/thunderstorms.test.ts` и браузерным сценариям.

## Сохранения, UI и проверки для каждого плана

- `src/persistence/schema.ts` проверяет ссылки и данные, последовательно мигрирует старые версии; текущий `SAVE_VERSION = 32` в `src/core/types.ts`. Не жёстко задавать эту версию в новых планах: при реализации смотреть актуальную.
- `src/persistence/storage.ts`: IndexedDB, последовательная запись, сохранение старой записи при неудачной загрузке. Новые данные должны иметь валидатор и миграцию при изменении формата.
- Мир сохраняет активную работу, пути, груз, стройку, болезни, сценарии, социальные связи и RNG. После загрузки должны сохраняться фактическое состояние и одинаковое дальнейшее развитие при одинаковых командах.
- Не использовать `Math.random()`/часы браузера для решений симуляции. Для новых сущностей проверять лимиты, смерть/удаление цели, очистку ссылок, паузу и сохранение во время действия.
- UI: инструменты формируются из Registry; текущие данные о деревне доступны в подсказках и соответствующем UI. Существующая панель общества может быть скрыта стилями; не считать поле в `src/ui.ts` гарантированно видимым.
- `src/i18n.ts`: английский, русский, китайский, японский, испанский. Новый пользовательский текст добавлять во все поддерживаемые языки, не переводить сохранённые идентификаторы.
- `package.json`: `npm run build` = TypeScript + Vite; `npm test` = Vitest без benchmark; `npm run test:e2e` = Playwright; `npm run benchmark` = отдельные замеры.
- Браузеры в `playwright.config.ts`: Chrome, Firefox, WebKit. Для небольшого плана выбирать относящиеся тесты; проверять живой UI без замены JS-модулей тестовыми заглушками, если утверждается реальная интеграция.
- При расширении элемента проверять цепочку «источник → действие конкретного участника → изменение состояния → видимое последствие», недоступный путь, нехватку ресурса, прерывание голодом/опасностью, уничтожение участника/цели, загрузку в середине процесса.
